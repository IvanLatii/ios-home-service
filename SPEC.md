# Home Service — специфікація прототипу

> Джерела: Figma-файл `Home Service — iOS` (сторінка Prototype), опис флоу від автора, структура категорій.
> Цей документ — єдине джерело правди про обсяг. Якщо чогось тут немає — цього немає в прототипі.

---

## 1. Що будуємо

Веб-прототип мобільного застосунку для замовлення побутових послуг.
Користувач — **клієнт**, який хоче замовити майстра додому.

**Головний сценарій (happy path):**
Головна → пошук послуги → деталі заявки → дата й час → вибір майстра → підтвердження замовлення → успіх → повернення на головну зі зміненим станом.

**Технічно:** Next.js 16 (App Router), TypeScript, Tailwind, shadcn/ui. Дані мокові, бекенду немає.

---

## 2. Рішення про обсяг

| Рівень | Що входить | Поведінка |
|---|---|---|
| **Працює по-справжньому** | Пошук, усі 8 категорій, будь-яка послуга → форма заявки, усі 4 кроки заявки, екран успіху, зміна стану головної | Повна логіка на мокових даних |
| **Інертне** | Бонуси, нотифікації, вкладки таб-бару крім Home, кнопка «+», банери, редагування контакту й адреси | Видно, клік нічого не робить |
| **Не робимо** | Авторизація, оплата, бекенд, чат, карта, реальне завантаження файлів, адмінка | Відсутнє повністю |

**Принцип:** будь-який клік або веде далі по сценарію, або нічого не робить. Білих екранів і 404 бути не має.

## 3. Зафіксовані рішення

1. **Мова інтерфейсу — англійська**, як у макеті. Валюта ₴, місто Rivne, телефон +380 лишаються. Українською пишуться тільки коментарі в коді й документація.
2. **Формула підсумку:** `Total = Estimated cost − Bonuses applied`. Travel fee вже входить у Estimated cost, тому в підсумку це довідковий рядок. Підписати його `Travel fee (included)`, інакше читається як помилка розрахунку.
3. **iOS-обгортка відтворюється повністю** — springboard, splash, статус-бар, home indicator, клавіатура. Деталі реалізації — розділ 6.0.

## 5. Модель даних

```ts
type Category = {
  id: string
  slug: string
  title: string
  icon: string        // емодзі
  serviceIds: string[]
}

type SelectField = {
  id: string
  label: string       // "Problem type"
  required: boolean
  options: { id: string; label: string }[]
}

type Service = {
  id: string
  slug: string
  categoryId: string
  title: string       // "Faucet repair"
  basePrice: number   // грн
  fields: SelectField[]
}

type Master = {
  id: string
  name: string
  initials: string
  rating: number
  reviews: number
}

type OrderDraft = {
  serviceId: string
  answers: Record<string, string>   // fieldId -> optionId
  hasMaterials: boolean
  photoIds: string[]
  comment: string
  date: string | null
  timeSlot: string | null
  masterMode: 'auto' | 'manual'
  useBonuses: boolean
}
```

**Ключове рішення:** dropdown-и описані даними (`fields`), а не захардкожені. Тому форма однакова для будь-якої послуги, і всі 64 послуги працюють з одного шаблону.

По 8 послуг у кожній — повний перелік у документі категорій.

## 6. Екрани

### 6.0 iOS-обгортка

**Принцип: обгортка — це картинки, а не код.** Усе нижче експортується з Figma у PNG @2x і кладеться в `public/chrome/`. Верстати ці елементи вручну заборонено — це витрата часу без виграшу.

| Елемент | Реалізація | Висота |
|---|---|---|
| Springboard `Home-phone 1` | Один PNG на весь екран + одна клікабельна зона на іконці Home Service | 874 |
| Splash `402 / Splash` | PNG, автоперехід на `/` через 1000 мс | 874 |
| Статус-бар | PNG, `position: sticky`, зверху кожного екрана | 62 |
| Home indicator | PNG, притиснутий донизу | 34 |
| Клавіатура | PNG, виїжджає знизу при фокусі в полі, `transform: translateY` + transition 250 мс | 317 або 342 |

**Клавіатура — декоративна.** Користувач друкує справжньою клавіатурою в справжній `<input>`. Намальована лише присутня в кадрі й піднімає контент.

**Обмеження:** на реальному мобільному пристрої фокус викличе системну клавіатуру поверх намальованої. Демо записується на десктопі у вікні шириною 402px. Це прийнятно для прототипу і має бути згадано в README.

**Маршрути обгортки:**
- `/springboard` — стартова точка демо
- `/splash` — проміжна, автоперехід
- Решта екранів рендерять статус-бар і home indicator через спільний layout

---

### 6.1 Головна `/`

**Блоки згори вниз:**
1. Тулбар: іконка локації + назва міста, справа лічильник + іконка дзвінка
2. Статистика: `Bonuses 487 ₴` | `Orders 2` | кнопка 48×48
3. Картка активного замовлення — **прихована** у стані 1, **видима** у стані 2
4. Поле пошуку (не інпут, а кнопка → веде на `/search`)
5. Заголовок + горизонтальний слайдер із 8 таб-категорій
6. Заголовок + сітка з 8 category-card, 2 колонки × 4 рядки, картка 192×52
7. Банери: один великий 386×168 + два малих 177×100
8. Таб-бар: 5 вкладок, центральна — кнопка «+»

**Два стани:**

| | Стан 1 (початковий) | Стан 2 (після замовлення) |
|---|---|---|
| Картка замовлення | прихована | видима |
| Bonuses | 487 ₴ | 101 ₴ |
| Orders | 2 | 3 |

Стан 2 показується після повернення з екрана успіху. Зберігати у sessionStorage.

**Поведінка:** клік по будь-якій категорії → `/search` з попередньо застосованою категорією. Клік по полю пошуку → `/search`. Банери, бонуси, дзвінок, «+», інші вкладки — інертні.

---

### 6.2 Пошук `/search`

**Стан A — фокус, порожній запит:**
- Інпут у фокусі + кнопка скасування 56×56 праворуч
- Заголовок `History` + 3 рядки історії (висота 24)
- Заголовок `Services` + 4 картки послуг (386×48)

**Стан B — введено текст:**
- `History` **замінюється** на `Categories` — горизонтальний ряд чипів
- `Services` лишається, релевантні збіги **підсвічені**
- Достатньо ввести `Fau`, щоб знайшлась `Faucet repair`

**Логіка:** фільтр по підрядку в назві послуги, регістронезалежний. Збіг підсвічується в тексті. Порожній результат → рядок «Нічого не знайдено» + пропозиція подивитись категорії.

**Перехід:** клік по послузі → `/order/[serviceId]/details`.

### 6.3 Деталі заявки `/order/[serviceId]/details`

Заголовок тулбара: `Faucet repair · Step 1 of 4`.

**Блоки:**
1. Три dropdown 386×56 — відкривають нижню модалку зі списком опцій
2. Кнопка-посилання під ними (213×24)
3. `I have materials` + toggle — **необов'язково**
4. Заголовок + зона завантаження фото 386×72 — **необов'язково**
5. Заголовок + textarea 386×138 для коментаря — **необов'язково**
6. `Estimated cost` — `0 ₴` доки не заповнені dropdown-и, далі перераховується
7. Нав: дві кнопки 173×56 — назад і `Continue`

**Модалка вибору опції:** заголовок із назвою поля + кнопка закриття 40×40, список Select-рядків 386×56. Висота модалки залежить від кількості опцій.

**Модалка фото:** заголовок `Add photos`, сітка 3×3 з дев'яти зображень-заглушок, кнопка внизу `Add N photos` (лічильник живий). Після додавання на екрані з'являється блок `3 Photos · 4.1 MB` + кнопка очищення + три photo-card по 60px.

**Валідація:** `Continue` активна лише коли заповнені всі три dropdown.

**Розрахунок вартості:** `basePrice` послуги. У макеті проміжні стани показують 2 150 → 1 820,50 → 1 500 — це наслідок різних комбінацій опцій. Достатньо задати коефіцієнт на кожну опцію в моці.

### 6.4 Дата й час `/order/[serviceId]/schedule`

`Step 2 of 4`.

**Блоки:**
1. Контактна особа: іконка, `Ivan L`, олівець, `+380 68 006 54 88`
2. Адреса: іконка, `Shevchenka st., 47.`, олівець, `Rivne, Entrance 1, 5th Floor, Apartment 28`
3. Календар 386×336 — місяць, вибір одного дня
4. Слоти часу: 6 кнопок 191×48, 2 колонки × 3 рядки
5. Одна кнопка `Continue` 354×56

**Поведінка:** олівці інертні — дані підставлені. `Continue` активна після вибору дня і слоту. Еталонний вибір із демо: **17 число, 17:00–19:00**.

---

### 6.5 Вибір майстра `/order/[serviceId]/master`

`Step 3 of 4`. Два варіанти-радіо:

**`Match me auto`** — тег, опис «We find the best available master based on ratings and proximity. Fastest option.», три накладені аватари 40×40, п'ять зірок, рейтинг `4.9`, підпис `Top-rated masters nearby`. **Обраний за замовчуванням.**

**`Choose master manually`** — опис «It may take longer and cost more than usual.» Вибір перемикається, але списку майстрів у прототипі немає.

Знизу інфо-блок: «All masters are verified, insured, and have passed background checks.»

*Опційно, якщо буде час:* стан «немає доступних майстрів» з найближчим вільним часом і двома кнопками — обрати інший час / підтримка.

---

### 6.6 Підсумок `/order/[serviceId]/review`

`Step 4 of 4`.

1. Сім рядків summary-item 354×48 — послуга, обрані опції, матеріали, фото, дата, час, майстер. Значення тягнуться з чернетки.
2. `Use bonuses` + сума + toggle
3. Три рядки розрахунку: `Estimated cost 1,500.00 ₴`, `Travel fee (included) 100 ₴`, `Bonuses applied −487 ₴`
4. `Total to pay` — перераховується при перемиканні toggle
5. Інфо: «Final cost may vary depending on the actual scope of work and materials required.»
6. Кнопка `Confirm order` 354×56

**Формула:** `Total = Estimated cost − (useBonuses ? bonusBalance : 0)`
Travel fee входить у Estimated cost і в сумі не додається — тому підпис `(included)` обов'язковий.
Еталон: 1 500 − 487 = **1 013 ₴**. З вимкненим toggle: 1 500 ₴.

---

### 6.7 Успіх `/order/[serviceId]/success`

Нижня модалка на всю висоту: іконка-щит 160×160, заголовок, підзаголовок, дві кнопки 342×56. Головна — `Back to home`, веде на `/` у **стані 2**.

## 8. Дизайн-константи

- Базова ширина макета — **402px** (iPhone 16 Pro). Верстаємо mobile-first, на десктопі центруємо колонку 402px.
- Горизонтальний відступ контенту — **24px** від краю
- Контейнери карток — **8px** від краю, внутрішній відступ **16px**
- Висоти: кнопка 56, dropdown 56, таб 48, photo-card 60, аватар 40, іконка 20 або 16, toggle 56×24
- Таб-бар: 68 + 34 home indicator

**Кольори, шрифти, радіуси та тіні в цьому документі свідомо не зафіксовані** — їх треба брати з Figma перед версткою кожного екрана, а не з пам'яті.

## 10. Порядок робіт

1. `src/data/` — категорії, послуги, поля, майстри
2. Експорт обгортки з Figma у `public/chrome/` — робиться руками, не агентом
3. Спільні компоненти: `PhoneShell` (статус-бар + home indicator), `Toolbar`, `PrimaryButton`, `BottomSheet`, `FakeKeyboard`
4. Головна, стан 1
5. Пошук із клавіатурою
6. Крок 1 — деталі з модалками
7. Кроки 2–4
8. Успіх і стан 2 головної
9. Springboard і splash — останніми, бо вони не блокують решту
10. Прохід усього сценарію, чистка
11. Деплой, README, Loom

Комміт після кожного пункту.

**Springboard і splash навмисно в кінці.** Вони найпомітніші, тому спокуса почати з них велика — але вони нічого не розблоковують. Якщо часу забракне, прототип без них лишається цілим, а без форми заявки — ні.
